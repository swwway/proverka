# proverka — прибор проверки проектов: три исхода вместо двух (ЗЕЛЕНО, КРАСНО, НЕ ПРОВЕРЕНО)

**Статус:** инструмент (публичный репозиторий, лицензия MIT; в файлы не писать имена клиентов, контакты, цены, личное)
**Выложено:** не выкладывается. Распространяется копией скриптов в `~/.local/bin` (README, раздел «Установка»). Проверка на стороне GitHub — `.github/workflows/selftest.yml` (push в `main` и PR).

## Что это

CLI на Python (3.8+, без зависимостей) и три спутника. Читает `КАЧЕСТВО.yml` проекта и не даёт назвать зелёным то, что не проверено:
ноль запущенных проверок = «НЕ ПРОВЕРЕНО», а не «ЗЕЛЕНО». Коды возврата: `0` ЗЕЛЕНО, `1` КРАСНО, `2` НЕ ПРОВЕРЕНО.
Интерфейс и вывод на русском. Последняя работа (git log): журнал считается по последней записи, зубы мерят весь набор проверок, набор не усыхает при перезаведении.

## Как работать

| Задача | Команда |
|---|---|
| справка по режимам | `python3 proverka --help` (режимы: init, check, selftest, teeth, zadanie, gate, profile, watch) |
| установить | `cp proverka proverka-hook-push proverka-klyuchi proverka-vosstanovlenie ~/.local/bin/ && chmod +x ~/.local/bin/proverka*` |
| собрать | не требуется: скрипты без шага сборки |
| выложить | не выкладывается; правки — в ветку и PR, слияние в `main` — решение владельца |

## Проверки

| Что | Команда | Время |
|---|---|---|
| самопроверка прибора (17 подложенных порч, обязан поймать все) | `python3 proverka selftest` | ≈2 с (замер 15.09: 1,2 с) |
| синтаксис | `python3 -m py_compile proverka proverka-klyuchi proverka-vosstanovlenie && bash -n proverka-hook-push` | ≈1 с |

Запуск — по решению владельца проекта. Агенту: предложи одной строкой «Проверить прибор: `python3 proverka selftest`, ≈2 с? (да/нет)» и не запускай без «да».
Код возврата 0 у selftest без строки «поймал все порчи (17 из 17)» — не зелёное (так же считает CI). Не запускалось и не проверено: `proverka-vosstanovlenie` (нужен docker).

## Решения владельца — спрашивать

- публикация: слияние в `main`, релизы, любые правки README с заявлениями о приборе для внешних читателей;
- удаление или ослабление проб в `selftest` (число 17 зашито в README и в `selftest.yml`: менять согласованно);
- `proverka-klyuchi` не печатает значения секретов, только вид, отпечаток и файлы: это правило не ослаблять;
- сообщения людям и отправка в Telegram (токены только из `~/.config/proverka/telegram.env` или переменных окружения, в репозиторий не класть).

## Где что лежит

- `proverka` — основной прибор (один файл, ≈190 КБ), режимы из таблицы выше
- `proverka-hook-push` — pre-push турникет (быстрые проверки и поиск секретов); `proverka-klyuchi` — карта ключей; `proverka-vosstanovlenie` — учение по восстановлению баз
- `README.md` — установка, режимы, порядок применения к проекту; комментарии в коде описывают случаи, из которых выросли правила, их читать
- `КАЧЕСТВО.yml`, `ЗАДАНИЕ-ПРОВЕРКИ.md` — замеры прибора на самом себе (зубы 20–30% на 15.09: поймано 1 из 5 и 3 из 10; набор из одного selftest слабо ловит порчи)
